# Практические работы по системам параллельной обработки сигналов

## Практическая работа № 1

Условия находятся в `templates/1 Практическая работа 1.docx.md`, общие требования
к отчёту — в PDF в том же каталоге. Исходник задания 1:
`pr1/src/task1_unordered.c`. Отчёт: `pr1/reports/report.tex`.

### Что сделано

- Все ненулевые процессы отправляют свой ранг процессу 0.
- Процесс 0 печатает свой ранг, принимает сообщения с `MPI_ANY_SOURCE`
  и печатает значение и отправителя.
- Исправлено зависание: требуется `p-1` приёмов, а не `p`.
- Сборка с предупреждениями прошла; проверены 1 и 2 процесса и пять запусков
  на 8 процессах. Последовательности внесены в TeX-отчёт.

### Последовательность дальнейшей работы

1. Повторить запуски задания 1 на 1, 2, 4, 8, 16 процессах; при 8 процессах
   выполнить несколько повторов. Убедиться, что каждый ранг встречается один
   раз, первым идёт 0 и программа завершается. Сделать скриншоты.
2. Объяснить порядок: после нуля печатаются сообщения, выбранные последовательными
   вызовами `MPI_Recv`; между разными отправителями порядок не гарантируется.
   Он не обязан меняться при каждом запуске.
3. Создать `pr1/src/task2_ordered.c` на основе первой программы. В цикле
   `for (int i = 1; i < process_count; i++)` заменить источник
   `MPI_ANY_SOURCE` на `i`. Отправку оставить прежней.
4. Повторить проверки второй программы. Ожидаемый порядок: 0, 1, ..., p-1.
   Сравнить обе версии и сделать скриншоты.
5. Для общих требований отчёта подготовить экспериментальные версии с изменяемым
   размером сообщения. Вынести подготовку и печать за замер, использовать
   `MPI_Wtime`, максимум локальных времён через `MPI_Reduce`/`MPI_MAX`,
   прогрев и несколько повторов. Подробная методика есть в отчёте.
6. Измерить обе версии при p=1,2,4,8,16 (при необходимости 32) и нескольких
   размерах сообщения, записать условия эксперимента. Запуски с переподпиской
   ядер отметить отдельно. Построить графики времени.
7. Согласовать трактовку ускорения: при p=1 исходная программа ничего не
   пересылает, а при фиксированном размере одного сообщения общая нагрузка
   растёт с p. Для обычного ускорения нужна сопоставимая последовательная
   задача с тем же общим объёмом работы; формулы и ограничение указаны в отчёте.
8. Заполнить титульный лист, добавить схему сети Петри по формальному описанию,
   листинг второй программы, скриншоты, таблицы, графики и итоговый анализ.
   Собрать PDF и проверить оформление.

### Компиляция и запуск

Команды выполняются из корня репозитория. Нужны CMake, C-компилятор
и реализация MPI. CMake находит MPI через стандартный `FindMPI`,
поэтому сборка не привязана к x86_64, конкретному компилятору или
фиксированному числу процессов.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
cmake --build build --target run_task1_p1
cmake --build build --target run_task1_p2
cmake --build build --target run_task1_p4
cmake --build build --target run_task1_p8
```

Цель `run_task1_all` запускает все заданные количества, а CTest позволяет
прогнать их как тесты:

```bash
cmake --build build --target run_task1_all
ctest --test-dir build --output-on-failure -j1
```

Список чисел процессов можно изменить при конфигурировании. Это именно
число **MPI-процессов**, а не архитектур CPU и не число потоков:

```bash
cmake -S . -B build -DSPOD_PROCESS_COUNTS="1;2;4;8;16"
```

Если процессов больше, чем доступных MPI-слотов, Open MPI можно настроить
через `-DMPIEXEC_PREFLAGS=--oversubscribe`. Переподписка полезна для функциональной
проверки, но искажает измерения производительности.

### Сборка отчёта

Нужен XeLaTeX с пакетами из преамбулы и шрифтом Tinos.
Персональные данные задаются командами `\University`, `\Department`,
`\StudentName`, `\StudentGroup`, `\TeacherName`, `\City`, `\Variant`.
Места для изображений выделены рамками `\placeholder{...}`; их можно заменить
на `\includegraphics[width=\linewidth]{screenshots/example.png}`.

```bash
cd pr1/reports
xelatex -interaction=nonstopmode -halt-on-error report.tex
xelatex -interaction=nonstopmode -halt-on-error report.tex
```

Имеющийся `report.pdf` — прежняя версия: после изменений TeX он не пересобран,
поскольку в среде проверки отсутствует TeX-компилятор. Разделы с ещё не
проведёнными экспериментами явно отмечены в исходнике отчёта.
