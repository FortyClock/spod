### Компиляция и запуск

Команды выполняются из корня репозитория. Нужны CMake, C-компилятор
и реализация MPI. CMake находит MPI через стандартный `FindMPI`,
поэтому сборка не привязана к x86_64, конкретному компилятору или
фиксированному числу процессов.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
cmake --build build --target run_task1_p1
cmake --build build --target run_task1_p2
cmake --build build --target run_task1_p4
cmake --build build --target run_task1_p8
```

Для задания 2 используются аналогичные цели:

```bash
cmake --build build --target run_task2_p1
cmake --build build --target run_task2_p2
cmake --build build --target run_task2_p4
cmake --build build --target run_task2_p8
cmake --build build --target run_task2_all
```

Экспериментальные программы собираются отдельно от основных заданий:

```bash
cmake --build build --target task1_unordered_benchmark
cmake --build build --target task2_ordered_benchmark
```

Размер сообщения для целей запуска задаётся при конфигурировании:

```bash
cmake -S . -B build -DSPOD_BENCHMARK_MESSAGE_SIZE=1024
cmake --build build --target run_task1_benchmark_p4
cmake --build build --target run_task2_benchmark_p4
```

До завершения исходников benchmark эти цели могут не собираться;
поэтому они не включены в обычную цель `all`.

Цель `run_task1_all` запускает все заданные количества, а CTest позволяет
прогнать обе программы как тесты:

```bash
cmake --build build --target run_task1_all
ctest --test-dir build --output-on-failure -j1
```

Список чисел процессов можно изменить при конфигурировании. Это именно
число **MPI-процессов**, а не архитектур CPU и не число потоков:

```bash
cmake -S . -B build -DSPOD_PROCESS_COUNTS="1;2;4;8;16"
```

По умолчанию цели запуска передают Open MPI флаг `--use-hwthread-cpus`, поэтому
аппаратные потоки учитываются как доступные слоты. Если процессов больше, чем
аппаратных потоков, можно разрешить переподписку при конфигурировании:

```bash
cmake -S . -B build \
  -DSPOD_MPIEXEC_PREFLAGS="--use-hwthread-cpus;--oversubscribe"
```

Переподписка полезна для функциональной проверки, но искажает измерения
производительности.

## Практическая работа № 3

Условие: `templates/task3`, вариант 7. Основная программа:
`pr3/src/reduce_sum.c`. В каждом из K процессов создаётся массив длины
K + 5, а `MPI_Reduce` с `MPI_SUM` складывает массивы поэлементно.
Процесс 0 выводит результат. Для заполнения `a[r][i] = i * r`
ожидаемый результат: `b[i] = i * K * (K - 1) / 2`.

### Текущее состояние

- Код скомпилирован с C11 и `-Wall -Wextra -Wpedantic`.
- Проверены запуски на 1, 2 и 4 процессах; результаты соответствуют формуле,
  коды завершения — 0. Это функциональная проверка, не бенчмарк.
- Подготовлен отчёт: `pr3/reports/report.tex`. Оформление и титульный лист взяты
  за основу из практической № 2. Добавлены сеть Петри, скриншоты,
  таблица, графики времени и анализ. Независимое исследование размера
  массива и измерения ускорения ещё предстоят.

### Сборка и запуск

В VS Code через CMake Tools: `CMake: Configure`, затем
`CMake: Set Build Target` → `reduce_sum` (или `all`), затем кнопка Build.
Из терминала:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target reduce_sum
mpirun --use-hwthread-cpus -np 4 ./build/reduce_sum
```

### Автоматический прогон бенчмарка № 3

Скрипт выполняет семь отдельных MPI-запусков на каждое количество процессов
(по умолчанию 1, 2, 4, 8, 16), без прогрева. Каждый запуск бенчмарка уже
измеряет 1000 редукций и выводит среднее время одной; скрипт повторно
на 1000 не делит. Итог — медиана семи значений.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target reduce_sum_benchmark
python3 pr3/scripts/run_benchmark.py --oversubscribe
```

Если процессов не больше доступных MPI-слотов, `--oversubscribe` можно
опустить. Флаг только разрешает переподписку; факт её использования зависит
от числа процессов и ресурсов. Параметры можно менять:

```bash
python3 pr3/scripts/run_benchmark.py --processes 1 2 4 8 --repetitions 7
```

Результаты в `pr3/results` (повторный прогон перезаписывает их):

- `reduce_sum_benchmark_raw.csv` — все 35 замеров, секунды на вызов.
- `reduce_sum_benchmark_summary.csv` — минимум, медиана, максимум в мкс.
- `reduce_sum_benchmark_metadata.json` — окружение, параметры и команды.
- `reduce_sum_benchmark_table.tex` — таблица, подключённая к отчёту.

Начальные результаты получены в среде агента на Intel Core i3-12100
с 8 логическими CPU, Open MPI 4.1.6, GCC 13.3.0, Release;
при 16 процессах использовалась переподписка. Это не замеры компьютера
пользователя. При повторении на другом компьютере обновить описание среды
в отчёте и пересобрать PDF. Длина массива пока равна K + 5; эта серия
не заменяет исследование нескольких независимых размеров массива.
