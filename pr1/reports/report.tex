\section{Цель работы}

Познакомиться с запуском MPI-программы на различном числе процессов,
обменом сообщениями между процессами и способами управления порядком вывода
результатов параллельного выполнения.

\section{Формулировка задания}

\textbf{Задание 1.} Все процессы, кроме процесса с рангом 0, передают
значение своего ранга нулевому процессу. Процесс с рангом 0 сначала печатает
значение собственного ранга, затем принимает сообщения с рангами остальных
процессов и также выводит их. Порядок приёма сообщений заранее не определён и
может изменяться от запуска к запуску.

Необходимо несколько раз запустить программу при фиксированном числе
процессов (например, при восьми), проанализировать порядок вывода сообщений и
сформулировать правило, которое его определяет.

\textbf{Задание 2.} Модифицировать программу так, чтобы порядок вывода
сообщений соответствовал номерам процессов. Сравнить результаты работы двух
вариантов программы.

\section{Описание алгоритмов и состояние реализации}

Реализован вариант задания 1 на языке C с MPI. Все $p$ процессов вызывают
\texttt{MPI\_Init}, определяют ранг и число процессов. Каждый процесс с
рангом $i>0$ отправляет одно целое число $i$ процессу 0 с тегом 0.
Процесс 0 печатает собственный ранг и выполняет ровно $p-1$ операций
\texttt{MPI\_Recv} с источником \texttt{MPI\_ANY\_SOURCE}, печатая
полученное значение и фактического отправителя из \texttt{MPI\_Status}.
Все процессы завершают работу через \texttt{MPI\_Finalize}.

При проверке исправлена граница цикла: ранее выполнялось $p$ приёмов,
хотя отправлялось только $p-1$ сообщений. Лишний приём приводил к зависанию.
При $p=1$ исправленная программа только печатает ранг 0 и завершается.

Для задания 2 необходимо создать отдельную программу: в цикле по
$i=1,\ldots,p-1$ указывать источником приёма $i$ вместо
\texttt{MPI\_ANY\_SOURCE}. Отправители могут работать одновременно;
порядок печати задаёт процесс 0. Эта версия на момент подготовки отчёта
ещё не реализована.

\section{Формальное описание с помощью сетей Петри}

Используется параметризованная сеть Петри с цветными фишками.
Для каждого $i\in\{1,\ldots,p-1\}$ место $A_i$ содержит одну начальную
фишку готовности отправителя, $B_i$ обозначает завершение его обмена.
Место $R$ содержит фишку состояния принимающего процесса $(k,L)$:
число принятых сообщений и последовательность уже напечатанных рангов.
Начальное место $Z$ содержит одну фишку готовности процесса 0.
Место $F$ обозначает завершение приёма.

Переход $t_0:Z\to R$ печатает 0 и создаёт фишку $(0,[0])$.
Для каждого $i>0$ переход обмена имеет входы $A_i,R$ и выходы $B_i,R$:
\[
 A_i+R(k,L)\xrightarrow{t_i}B_i+R(k+1,L\mathbin{\|}[i]).
\]
Функционал $t_i$: передать ранг $i$, принять его процессом 0 и напечатать.
Обмен отправителя с получателем здесь моделируется одним совместным
переходом; внутренняя буферизация MPI абстрагирована.
В неупорядоченном варианте допустим любой ещё не сработавший $t_i$.
В упорядоченном варианте дополнительное условие перехода: $i=k+1$.
Переход $t_f:R\to F$ разрешён только при $k=p-1$; он завершает фазу приёма.

Каждый $t_i$ срабатывает ровно один раз, поскольку расходует единственную
фишку $A_i$. Единственная фишка $R$ обеспечивает последовательную печать
процессом 0. Итоговый список содержит все ранги ровно по одному разу.
При $p=1$ после $t_0$ сразу разрешён $t_f$.

Передаются сообщения с целыми числами, а не сигналы ОС.

\section{Методика измерения времени}

Замеры времени пока не выполнены: текущий код не содержит измерений и
параметра объёма данных. Для выполнения общих требований к отчёту нужна
отдельная экспериментальная модификация обеих программ. Обозначим через
$n$ число целых чисел в сообщении каждого отправителя; например,
$n=1,1024,65536$. В исходной постановке $n=1$.
Подготовку массивов и печать следует вынести за измеряемый участок.
Перед обменом выполнить \texttt{MPI\_Barrier}, затем на каждом процессе
снять \texttt{MPI\_Wtime}, выполнить обмен и повторно снять время.
За время опыта принять максимум локальных длительностей, вычисленный
через \texttt{MPI\_Reduce} с операцией \texttt{MPI\_MAX} после замера.
Полученные ранги сохранять и печатать после окончания измерений.

Для каждой пары $(p,n)$ провести прогрев и, например, десять измерений;
в таблицу внести медиану. Проверить $p=1,2,4,8,16$ и при необходимости 32.
Зафиксировать модель CPU, число физических ядер, ОС, версию MPI,
параметры сборки и размещение процессов. Запуски с числом процессов выше
числа доступных ядер отмечать отдельно: переподписка влияет на время.

При фиксированном $n$ суммарная передача равна $(p-1)n$ целых чисел:
при изменении $p$ меняется сама работа. При $p=1$ обмен отсутствует.
Поэтому отношение $T(1,n)/T(p,n)$ для исходного задания нельзя
интерпретировать как ускорение решения одной и той же задачи.
Для содержательного исследования ускорения требуется отдельно определить
фиксированный общий объём $N$, распределяемый по отправителям, и
последовательный алгоритм обработки того же объёма с временем
$T_{\mathrm{seq}}(N)$. Такой эксперимент является расширением задания;
его постановку следует согласовать с преподавателем. Для него
\[
 S(p,N)=\frac{T_{\mathrm{seq}}(N)}{T_p(N)},\qquad
 E(p,N)=\frac{S(p,N)}{p}.
\]
Для исходного обмена полезно сравнивать время двух вариантов при
одинаковых $(p,n)$, не обещая наличия ускорения.

\section{Сравнение и выводы}

Проверенный вариант задания 1 обеспечивает передачу рангов всех ненулевых
процессов процессу 0 и завершается корректно после исправления числа
приёмов. Повторные запуски подтвердили изменение порядка вывода.
Для задания 2 ожидается последовательность $0,1,\ldots,p-1$ благодаря
явному выбору отправителя; экспериментальная проверка ещё предстоит.

Приём от заданного источника может ожидать конкретный процесс, даже если
другие сообщения уже доступны. В обоих алгоритмах все сообщения принимает
один процесс, что ограничивает масштабируемость. Какой вариант быстрее
на данной машине, можно установить только измерениями.
После заполнения таблиц и графиков необходимо описать наблюдаемые изменения
времени, возможные точки перелома, влияние размера сообщения и числа ядер.
Выводы об ускорении до проведения этих экспериментов не формулируются.
